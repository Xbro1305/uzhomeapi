# UzHome — документация по доработкам

Сводка всех изменений: интеграция с 1С, магазин (корзина без регистрации),
Telegram-бот, админ-панель, перевод сайта на SSR и индексация, оптимизация фото.

> Секретные значения (токены, пароли) в этом документе не приводятся — только
> имена переменных окружения. Актуальные значения — в серверном `.env` и в
> заметках владельца.

## 2. Интеграция с 1С (приём остатков)

**Модель:** 1С сама шлёт остатки к нам (в базу 1С не заходим). Остаток
хранится по **коду номенклатуры** (`nomenclatureCode`), НЕ по артикулу.

**Эндпоинт:**
```
POST https://uzhome.ru/api/stock/sync
Authorization: Bearer <STOCK_INGEST_TOKEN>
```

**Принимает выгрузку любым способом** (сделано максимально терпимо к формату):
- Тело JSON при **любом** `Content-Type` (`application/json`, `text/plain`,
  `application/x-www-form-urlencoded`, с `charset`, без заголовка).
- **Файлом** — `multipart/form-data` (любое имя поля) или полем формы с JSON.

Реализация: в `src/index.js` сырое тело сохраняется в `req.rawBody` для всех
парсеров; на `/sync` дополнительно стоит `multer` (в память) для файлов;
`resolveBody()` в `src/routes/stock.js` достаёт позиции из любого источника.

**Форматы тела:** массив `[ {...}, {...} ]`, либо `{ "items": [...] }`, либо
одна позиция объектом.

**Распознаваемые поля** (маппер `src/utils/stockMapper.js`, любые написания
рус/лат): `code` (обязателен), `article`, `name`, `warehouse`, `quantity`,
`available`, `reserved`, `unit`, `price`, `rollLength`. Нераспознанное
сохраняется в `Stock.raw`.

**Подтверждённый формат 1С** (от Владимира):
```json
[{ "code": "НФ-00000071", "article": "1212-9 cw-1",
   "name": "Ткань напечатанная бязь, ...", "warehouse": "Основной склад",
   "quantity": 1950, "unit": "пог. м" }]
```
⚠️ **`quantity` в МЕТРАХ** (пог. м), не в рулонах.

**Режимы:**
- Дельта (по умолчанию) — обновляет присланные позиции.
- Полный снимок — `?mode=full`: позиции, которых нет в выгрузке, обнуляются
  (`quantity=0`); бронь при этом сохраняется. Слать одним запросом.

**Прочие эндпоинты остатков:**
- `GET /api/stock/availability?codes=CODE1,CODE2` — публичный, доступное к продаже.
- `GET /api/stock/admin` — список для админки (нужен JWT).
- `PUT /api/stock/admin/:code` — ручная правка количества.

Входящие выгрузки логируются в `pm2 logs uzhomeapi` (`[stock/sync] ...`).

Инструкция для 1С-специалиста — `docs/1C-STOCK-SYNC.md`.

## 3. Заказы без регистрации

**Модель продажи:** продаём **метражом**, шаг = длина рулона
(`Fabric.rollLength`, поле у ткани, по умолчанию 50 м). Клиент берёт метраж
кратно шагу, максимум = доступные метры. Доступно = `quantity − reserved`.

**Создание заказа:**
```
POST /api/orders
{ "customerName", "customerPhone", "comment",
  "items": [ { "nomenclatureCode": "НФ-000...", "meters": 100 } ] }
```
- Атомарная бронь в метрах (два заказа не заберут один остаток).
- Проверка кратности длине рулона (иначе `400`), проверка наличия (иначе `409`).
- Самовывоз: **«Иваново, Сосновая 1»** (в заказе и в уведомлении).

**Админ-эндпоинты:**
- `GET /api/orders/admin` (фильтр `?status=`)
- `PATCH /api/orders/admin/:id/status` — смена статуса.

**Статусы и бронь:**
- `new` — бронь стоит;
- `confirmed` — подтверждён, бронь сохраняется;
- `cancelled` — бронь снимается (возврат в доступное);
- `completed` — продано: списываем и `quantity`, и `reserved`.

Логика вынесена в `applyStatusChange()` — общая для админ-API и кнопок Telegram.

## 4. Telegram-бот (@uzhomeorder_bot)

Заказы и заявки с сайта приходят в группу **«УзХоме – заявки и заказы»**.

- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — в серверном `.env`.
- ⚠️ Если группу повысят до супергруппы, `chat_id` меняется — надо обновить
  `TELEGRAM_CHAT_ID` (текущий — супергруппный, начинается с `-100…`).

**Уведомление о заказе** содержит inline-кнопки: **✅ Подтвердить · 📦 Выполнен ·
❌ Отменить**. Нажатие меняет статус заказа (та же логика брони/списания) и
обновляет сообщение.

**Webhook для кнопок:**
```
POST /api/orders/tg/webhook
```
- Защита — секрет `TELEGRAM_WEBHOOK_SECRET` (проверяется по заголовку
  `X-Telegram-Bot-Api-Secret-Token`).
- Зарегистрирован через `setWebhook` (`allowed_updates=[callback_query]`).
- ⚠️ Пока webhook стоит, `getUpdates` не работает. Чтобы получить новый
  `chat_id` — временно `deleteWebhook`, затем вернуть `setWebhook`.

**Форма обращения** на сайте: `POST /api/contacts/message`
(`{ name, phone, email?, message? }`) → уведомление в ту же группу.

## 5. Витрина — магазин (корзина без регистрации)

- **Корзина** (`CartContext`, в памяти): метраж кратно длине рулона, максимум =
  доступно; новые товары добавляются **сверху**.
- **Выезжающая корзина** (`CartDrawer`): степпер метража, форма заказа
  (имя, телефон с маской **+7**, комментарий), **обязательная галка** согласия
  с политикой (кнопка заблокирована, пока не отмечена), текст самовывоза,
  экран успеха с номером заказа, обработка `409` (не хватило остатка).
- **Иконка корзины** в шапке со счётчиком.
- На карточках расцветок — **бейдж наличия** (метры) и кнопка **«В корзину»**
  (только у расцветок с привязанным кодом 1С и при наличии).
- **На витрине показываются только привязанные к 1С расцветки.** Ткань без
  единой привязанной расцветки скрыта целиком.
- **Форма обращения**: маска телефона +7, валидация имени/телефона/e-mail.

## 6. Админ-панель

- **Заказы** (новый раздел): список, фильтр по статусу, кнопки
  Подтвердить / Выполнен (списать) / Отменить (снять бронь).
- **Остатки 1С** (новый раздел): таблица последних данных из 1С, правка
  количества вручную, поиск, **фильтр «Привязанные / Не привязанные»** со
  счётчиками и цветной индикатор у каждой строки.
- **Ткани**:
  - у ткани — поле **«Длина рулона»** (шаг продажи, по умолчанию 50 м);
  - у расцветки — поле **«Код 1С»** с кнопкой **«Выбрать»** → модалка остатков
    (`StockPicker`) с поиском (по умолчанию по артикулу расцветки); индикатор
    привязки на карточке.
- **Связывание кода 1С ↔ расцветка — с двух сторон:**
  1. из карточки ткани («Выбрать» → выбрать позицию остатка);
  2. из таблицы остатков (клик по строке → `FabricColorPicker` → выбрать
     расцветку).

Админка отдаётся как обычный клиентский SPA (не SSR) и всегда `noindex`.

## 7. Перевод сайта на SSR и индексация

Витрина переведена с CSR (SPA) на **SSR** (Vite SSR + Express, react-router
`StaticRouter`/`BrowserRouter`), дизайн и функционал 1:1.

- Публичные страницы (`/`, `/privacy`) рендерятся на сервере с полным
  контентом (данные тканей/контактов/сертификатов предзагружаются) — важно для
  индексации; далее страница «оживает» (гидрация) и обновляет данные.
- **Host-aware:** `uzhome.ru` индексируется, `ssr.uzhome.ru` — `noindex`
  (staging), `/admin` — всегда `noindex`.
- Фикс **без JS**: анимация появления секций включается только при наличии JS
  (класс `.js` на `<html>`), иначе контент виден сразу — для краулеров.

**SEO/индексация (отдаёт SSR-узел):**
- `robots.txt` (открыто, `/admin` закрыт, ссылка на sitemap),
- `sitemap.xml`,
- уникальные `title`/`description`/`canonical`/Open Graph на страницу,
- `og:image` (баннер) + Twitter Card — превью ссылки в мессенджерах,
- JSON-LD (Organization + WebSite) на главной,
- verification-теги Google/Яндекс (env `GOOGLE_SITE_VERIFICATION`,
  `YANDEX_VERIFICATION`).
- Зарегистрировано в Google Search Console и Яндекс.Вебмастере.

> Telegram кэширует превью ссылки. Для сброса — отправить URL боту
> **@WebpageBot**.

## 8. Оптимизация фотографий

Мобильный Safari падал из-за ~90 оригиналов фото (~53 МБ) на главной. Решение:
- `sharp` генерит **превью** (WebP ~1000px, ~100 КБ) — `src/utils/imageThumb.js`;
- поле `Fabric.colors[].thumbUrl`; превью создаётся при загрузке/замене фото;
- витрина грузит превью с `loading="lazy"`, **оригинал — только в лайтбоксе**;
- разовый бэкфилл `scripts/backfill-thumbs.mjs`.

Итог: **53 МБ → ~7 МБ** на странице, краш устранён.

## 9. Переменные окружения

**Бэкенд `/var/www/uzhomeapi/.env`:**
```
MONGODB_URI=...
JWT_SECRET=...
ADMIN_USERNAME=... / ADMIN_PASSWORD=...
PORT=5001
STOCK_INGEST_TOKEN=...            # токен приёма выгрузки 1С
TELEGRAM_BOT_TOKEN=...            # бот @uzhomeorder_bot
TELEGRAM_CHAT_ID=...              # id группы (супергруппа, -100...)
TELEGRAM_WEBHOOK_SECRET=...       # секрет webhook кнопок заказа
```

**SSR `uzhome-ssr` (через pm2, при запуске):**
```
NODE_ENV=production
PORT=5002
API_ORIGIN=http://127.0.0.1:5001
GOOGLE_SITE_VERIFICATION=...
YANDEX_VERIFICATION=...
# NOINDEX=true — принудительно закрыть всё от индексации (обычно не задаётся)
```
⚠️ При ручном пере-запуске `uzhome-ssr` (`pm2 delete` + `pm2 start`) все эти
env нужно передать снова, иначе verification-теги/настройки потеряются.
