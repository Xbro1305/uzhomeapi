# Приём остатков из 1С → сайт UzHome

Инструкция для 1С-специалиста. Мы **не заходим в базу 1С** —
наоборот, **1С сама отправляет остатки к нам** обычным HTTP-запросом.

## Куда слать

```
POST https://uzhome.ru/api/stock/sync
Content-Type: application/json
Authorization: Bearer <ТОКЕН>
```

Endpoint защищён токеном — **его нужно передавать в каждом запросе** (см.
раздел «Токен»). Без токена или с неверным — ответ `401`.

## Что слать

Тело запроса — JSON. Подходит любой из трёх видов:

```jsonc
// 1) массив позиций
[ { ... }, { ... } ]

// 2) объект с полем items
{ "items": [ { ... }, { ... } ] }

// 3) одна позиция
{ ... }
```

**Названия колонок пока можно любые** — приёмник сам распознаёт поля по
множеству вариантов написания (рус/лат, разный регистр, пробелы). Всё, что
он не распознал, всё равно сохраняется целиком в поле `raw` — ничего не
теряется.

**Единственное обязательное поле — КОД номенклатуры.** По нему остаток
связывается с товаром на сайте. Артикул для связи не годится — он
повторяется у разных расцветок.

### Распознаваемые поля

| Наше поле  | Что значит                       | Примеры названий колонок (любой из) |
|------------|----------------------------------|-------------------------------------|
| code ✅     | Код номенклатуры (обязателен)    | `Код`, `КодНоменклатуры`, `code`, `Kod`, `id`, `Ссылка` |
| article    | Артикул                          | `Артикул`, `article`, `sku` |
| name       | Наименование                     | `Наименование`, `Название`, `Номенклатура`, `name` |
| warehouse  | Склад                            | `Склад`, `warehouse`, `sklad` |
| quantity   | Остаток (в рулонах/штуках)       | `Количество`, `Остаток`, `qty`, `ВНаличии` |
| available  | Доступно к продаже               | `Доступно`, `Свободно`, `available` |
| reserved   | Резерв                           | `Резерв`, `reserved` |
| unit       | Единица измерения                | `ЕдИзм`, `Единица`, `unit` |
| price      | Цена (справочно)                 | `Цена`, `Стоимость`, `price` |
| rollLength | Метраж одного рулона             | `ДлинаРулона`, `Метраж`, `Длина`, `length` |

Числа можно слать как `12`, `"12,5"`, `"1 200"` — распознаются.

## Пример запроса

```bash
curl -X POST https://uzhome.ru/api/stock/sync \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <ТОКЕН>" \
  -d '[
    { "Код": "УТ-000123", "Артикул": "A1", "Наименование": "Бязь",
      "Склад": "Основной", "Количество": 12, "ЕдИзм": "рулон",
      "ДлинаРулона": 50, "Цена": 2500000 },
    { "Код": "УТ-000124", "Наименование": "Сатин", "Доступно": 7 }
  ]'
```

## Что вернётся

Ответ сразу показывает, что распозналось — удобно для проверки формата:

```json
{
  "message": "Принято",
  "received": 2,
  "saved": 2,
  "skipped": 0,
  "recognizedFields": ["code", "article", "name", "warehouse", "quantity", "unit", "rollLength", "price"],
  "skippedExamples": [],
  "sampleSaved": {
    "nomenclatureCode": "УТ-000123",
    "article": "A1",
    "name": "Бязь",
    "quantity": 12,
    "price": 2500000,
    "lastSyncedAt": "2026-07-28T10:00:00.000Z"
  }
}
```

- `received` — сколько позиций пришло.
- `saved` — сколько сохранено/обновлено.
- `skipped` — сколько пропущено (у них не нашёлся КОД); в `skippedExamples`
  видно, что именно пришло.
- `recognizedFields` — какие поля распознались. Если чего-то не хватает —
  пришлите пример колонки, расширим словарь.

## Как часто слать

По расписанию (например, раз в 10–15 минут или по факту движения). Каждая
позиция обновляется по коду (upsert): новые добавляются, существующие
перезаписываются.

## Полная выгрузка vs. дельта (важно для автосинхронизации)

Есть два режима — выбирается тем, **как вы шлёте**:

**1. Дельта (по умолчанию).** Шлёте только изменившиеся позиции. Всё, что
не пришло, остаётся как было. Ничего дополнительно указывать не нужно.

**2. Полная выгрузка (снимок всех остатков).** Шлёте сразу ВСЕ товары
одним запросом и помечаете запрос как полный:

```
POST /api/stock/sync?mode=full
```

(либо в теле-объекте добавить `"full": true`). В этом режиме позиции,
которых **нет** в снимке, автоматически обнуляются (`quantity = 0`) — чтобы
распроданный/снятый товар не «висел» в наличии на сайте. Бронь по нашим
заказам при этом сохраняется. В ответе поле `prunedToZero` покажет, сколько
позиций обнулилось.

> ⚠️ Полный снимок должен приходить **одним запросом**. Если выгрузка
> идёт постранично (несколько запросов подряд) — режим `full` включать
> **нельзя**: первая страница обнулит товары из остальных. В этом случае
> шлите как дельту.

**Что выбрать?** Если 1С удобно раз в N минут выгружать весь остаток
целиком — используйте `?mode=full`, это надёжнее всего (сайт всегда точно
соответствует 1С). Если выгружаются только движения — оставляйте дельту.
Напишите, какой вариант у вас — подскажем оптимально.

## Токен

Endpoint защищён — токен передаётся в каждом запросе. Сам токен пришлём
отдельно (в репозиторий/документацию его не пишем — это секрет).

Добавьте к запросу один из заголовков:

```
Authorization: Bearer <ТОКЕН>
```

или

```
X-Ingest-Token: <ТОКЕН>
```

Без токена или с неверным — ответ `401 Неверный токен выгрузки`.
Если токен нужно сменить (утёк, ротация) — напишите, обновим на сервере.

## Важный вопрос (не технический)

Остатки из бухгалтерской базы отражают **текущее фактическое** наличие на
складе или учётные данные с задержкой (на дату закрытия периода)? Для
магазина критично — иначе можно продать то, что уже ушло.
